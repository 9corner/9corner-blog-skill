# 正文截图

截图由 agent 自己截，别等作者。关键是**截一张就把三样东西绑死**。

## 边写边截

截完立刻定下编号、文件名、图注，三条不许分开记：

```text
01  01-ssh连接.png   「在本地命令提示符里 ssh 连接 VPS，输入 yes 和密码后看到 root 提示符」
02  02-ufw.png       「放行 443 和 2222 这两条规则，顺序是放行在前、启用在后」
```

事后回头猜哪张对哪段，一定会错位，而且错位了看不出来。

## 存放与占位

图存仓库根 `shots/{slug}/`，文件名两位序号（已 gitignore）。正文按出现顺序写 `![图注](占位-01)`，序号和文件名对齐。

用 `占位-01` 而不是空的 `[]()`：页面上会显示成一枚裂图，扫一眼就知道哪张还没传，空 src 则静悄悄什么都不显示。

## URL 回填

作者照清单顺序传图床。上传后的文件名可能被换成 UUID 或哈希，也可能原样保留：**看得出是哪张就按名字对，看不出就按给 URL 的先后一一对应**。两种情况都不要重新判断每张图该放哪——你已经记录过顺序，重新判断只会引入新错误。

数量对不上（正文 12 处占位、URL 只给 10 条）就停下来问，不许猜。

填完回一张对照表：序号 / 图注原文 / URL 前 8 位。UUID 太长，前 8 位够作者核，又不会把表格撑爆。

**填进去的必须是绝对 URL。** Atom 和 RSS 输出全文，相对路径在阅读器里会变成「阅读器域名/images/xxx.png」，图必裂。UUID 永远不要自己编。

## 内容要求

- 截图先抹掉账号、邮箱、本机路径和密钥。
- 图注会渲染成图片下方的说明文字，写成一句完整说明，不要只写「截图」。
- 自制示意图（非封面）可放 `src/content/posts/images/` 用相对路径，但那个目录下的图会被无条件打进构建产物，别往里堆废图。

## 检查

`python scripts/check-posts.py 稿子.md` 会报「N 张图还没填 URL」和「图注太短」。

交付时在正文围栏外单独点明还有几张没填、分别在哪——埋在一千字里没人会注意，粘到 GitHub 才发现是裂图就晚了。
